1. Verdict

Buildable, yes — as a supervised co-editor, not an unsupervised one. The result is a real, editable Resolve project (timeline, node grades, Fusion comps, markers, versions), never a flattened MP4, and you can watch it work (Section 4). Three limits stay true: the API cannot create colour nodes or wheels (so grades go through templates), taste calls such as best take remain yours, and nothing here can promise flawless output. The promise is process quality: no silent failures, nothing irreversible, every decision explained and every run replayable.

Twelve principles

Learn principles, not pixels. Reference → observations → technique hypotheses → conditions → preferences → rules → execution strategy.

Specialists, not one giant model. VLM = creative director; solver = editor; Resolve = workstation.

Code computes numbers; the model chooses strategies and explains them.

The EDG is the source of truth. Resolve is the executor and renderer.

No raw model writes to Resolve. Plan → validator → policy → adapter.

Write → read back → verify. Never trust an unverified Resolve write.

Never destroy originals; work on new timelines and versions.

Templates only for Fusion.

Everything visible: every executor step emits an event and a breadcrumb inside Resolve.

Cache and version everything (model, schema, solver, template, Resolve versions).

Patch, don't rebuild.

Local-first. No cloud calls unless you switch them on.

Precedence ladder: 1 hard safety constraints → 2 your current instruction → 3 project Brief → 4 recent confirmed corrections → 5 high-confidence conditional rules → 6 universal principles → 7 low-confidence observations.

4.3 Follow-along mechanics

Order of work is chosen so you always watch something meaningful: assembly on the Edit page, then each shot's grade on the Color page, then Fusion comps on the Fusion page, then Deliver for renders. Resolve's OpenPage is documented; whether the viewport repaints during long calls is tested in G11.

4.6 Optional in-Resolve HUD

Scripts launched from Workspace ▸ Scripts can open a small window inside Resolve (Fusion's UI Manager). A thin script polls Mission Control's local endpoint and shows the current step plus a Stop button, so you do not need a second monitor. It must stay a thin client (no model code inside Resolve's process). VERIFY in G11; if it fails, the second-window Mission Control is the fallback.

4.7 Honest limits of “live”

API-driven, not mouse-driven. You will see results appear, not a cursor clicking. That is deliberate: it is what makes runs deterministic and verifiable. GUI-automation is not used.

Brain-phase work happens outside Resolve (analysis, SAM, planning). During it Resolve is idle and you watch Mission Control.

Resolve may not repaint during a long call. Page switching usually forces a refresh; G11 measures it.

Pause is honoured between calls, not mid-call. A running render stops only through StopRendering.

Clip selection and playhead are poorly controllable, so we never depend on them.

WATCH mode is slower on purpose; TURBO exists for when you trust a stage.

Gate G11 (live-follow test): run 20 timed steps across Edit, Color and Fusion pages while screen-recording. Pass: at least 18 of 20 results are visibly on screen within 1 second without manual refresh. Fallback: STEP mode plus markers, clip colours and Mission Control thumbnails.

Flight recorder (optional): ffmpeg -f gdigrab -framerate 15 -i title='DaVinci Resolve' -c:v libx264 -crf 28 run_r07.mp4 on Windows, started with the run and indexed by event timestamps.

8. Perception and style capsules

8.1 Reference ingestion chain

ffprobe → normalise (1080×1920, constant fps, range check) → PySceneDetect shots → adaptive frame sampling → OCR → audio analysis → motion → DINOv2 embeddings → VLM analysis → effect hypotheses → layer reconstruction → capsule. Analysis runs on a 720p proxy; originals are never touched. Every expensive result is cached under clip hash + analysis version + model version.

Adaptive sampling: 1–2 frames/s on ordinary shots; 5–10 frames/s around events (cuts, text appearance, fast motion, mask boundaries, transitions, zooms, speed ramps, music drops).

8.2 Layer reconstruction

Each shot becomes a layer stack, so the system learns how the image is built, not what it looks like:

BASE VIDEO ├─ grade (shadow/highlight tint, black point, rolloff) ├─ subject isolation (matte present? soft or hard?) ├─ typography (class, weight, position, animation) ├─ motion graphics / 3D ├─ effects (glow, grain, shake, aberration, vignette) └─ overlays

Effect classifier vocabulary: hard cut, dissolve, whip, zoom transition, speed ramp, freeze frame, motion blur, mask reveal, subject cutout, text behind subject, tracked text, screen replacement, 3D text, 3D camera move, glow, bloom, chromatic aberration, grain, shake, parallax, particles, vignette, split screen, picture-in-picture. The VLM proposes the meaning; deterministic CV confirms what it can.

8.3 Text analysis

Extract string, timing, box, size, weight, tracking, fill, outline, shadow, position and animation. Do not identify the exact font. Record a font class (for example condensed heavy sans) and map it to the nearest fonts in your installed-font registry.

8.4 Observed vs inferred

A finished reel hides its node graph and Fusion graph. Every capsule entry therefore separates observed behaviour (text vanishes behind the rider) from inferred implementation (subject matte likely; pre-composite is the alternative), with evidence frames and a confidence. If the method cannot be known, the capsule says so.

8.5 Evidence-based confidence

Never accept a model's self-reported confidence. Compute it from: cross-model agreement, temporal consistency across frames, deterministic CV confirmation (OCR confirms text, SAM confirms occluder), reference support count, your history with similar decisions, and implementation certainty.

8.6 Compression caveats and the calibration set

Platform re-encoding destroys grain and shifts chroma: use robust percentiles on mid-tones, treat saturation as relative, never trust one frame. Calibration set (once): apply 10 known looks to your own footage, re-encode reel-style, and confirm the estimators recover them. Fix perception before building on it.

8.7 Reference prompt skeleton

Analyze this video as a professional editor. Do not describe it generally.For each technique give: timestamps, observable evidence, observed vs inferredimplementation, purpose (what visual problem it solves), conditions under which itwould work, and confidence. Do not assume the treatment fits unrelated footage.Return JSON matching the supplied schema and nothing else.

9. The Style Brain

9.1 Storage

SQLite is authoritative (reference, frame, scene, shot, observation, technique, style_rule, exception, preference, correction, project, edit_plan, edit_action, qc_result); a vector index (FAISS or LanceDB) handles retrieval. Every rule stores provenance: source references, support count, contradiction count, confidence, created, last used, last confirmed.

9.2 Dimensions, profiles and reference weighting

Taste is stored per dimension: rhythm, colour, typography, composition, motion, masking, Fusion, audio. Two mechanisms keep genres from blending into mush:

Profiles isolate coherent modes (night-moto-cinematic, clean-daylight-moto, indoor-portrait). Rules are learned inside a profile and never averaged across profiles.

Dimension-specific reference weights are the only sanctioned way to borrow across references: colour from Reel A, typography from Reel B, rhythm from Reel C. Weights live in the Edit Spec (Section 6).

9.3 Universal principles, conditional rules, negatives, exceptions

Kind

Meaning

Example

Universal principle

Holds regardless of subject

Restrained typography; deliberate subject/environment colour separation

Conditional rule

WHEN context THEN treatment

WHEN night + isolated subject + cyan environment THEN cool shadows, warm highlights, crushed blacks, matte lift

Negative preference

Things you reject

Blue skin; zoom transitions on static shots; full-screen text

Exception

Context that overrides a general rule

Induction (conditional rules): build per-shot look vectors and descriptor vectors; search condition splits; accept a rule only with support of at least 8 shots across at least 3 reels, a meaningful effect size, and a gain over the universal baseline under leave-one-reel-out validation. The VLM names and explains the rule and lists counter-examples. You approve before it enters the KB.

Sample sizes (rules of thumb, confirm with your own validation curve): about 15–25 reels per profile for stable universal principles; about 40+ before rich conditionals appear; beyond roughly 100 per profile, variety of situations beats volume.

9.4 Effects are tools, not fetishes

Store every effect as purpose + conditions + implementation + fallback:

effect: title_3dpurpose: spatial emphasisconditions: [strong_perspective, controlled_camera, negative_space]implementation: {template: text3d_hover, nodes: [Text3D, Camera3D, Merge3D, Renderer3D]}fallback: text_2_5d_with_planar_track

Before applying any effect the planner must answer what problem does this solve? Glow needs a reason (emphasise practical lights), 3D text needs a spatial reason, and “the user once liked it” is not one.

9.5 Retrieval at plan time

For each target shot: compute descriptors; code evaluates which rule conditions are true; retrieve matching rules per dimension plus nearest exemplars by embedding; assemble a contextual style package with provenance. The planner retrieves rules, not “the closest Reel.”

9.6 Style Explorer and Reference Inspector (UI)

Browse My Style by dimension (preferred / avoid / references / confidence), and open any Reel to see each technique with timestamps, evidence and whether it was observed or inferred. You can see, correct and delete what the AI believes.

10. Planner, Edit Decision Graph, patches, modes

Reasoning loop for every decision: Observe → Classify → Compare → Choose → Implement → Verify. Example: observe night shot, warm skin, cool environment → compare reference separates warm/cool → choose preserve the relationship, not the absolute hue → implement cooler ambient shadows, controlled saturation → verify skin neutral, subject dominant.

Passes: (1) assembly: story, shot choice, pacing, music, basic captions, framing; (2) polish: colour, masks, Fusion, typography, SFX, micro-timing; (3) finishing: QC. Complex jobs run all three.

Division of labour: LLM = director (intent and meaning); solver = editor (timing, repetition limits, beat offsets, invariants); Resolve = workstation.

Read before writing. Before any change the adapter calls get_project_state, get_timeline_state, get_clip_state, get_color_state, get_fusion_state, get_render_state, so the plan reflects the project as it is now, not as remembered.

Patch schema (every chat instruction becomes one):

- op: replace  target: timeline.shot_04  field: source_clip  value: clip_019- op: modify  target: grade.shot_09  field: contrast  delta: -0.12- op: remove  target: layers[type=text3d]

11.3 Grading intent, then numbers

For each target shot compute brightness distribution, shadow and highlight temperature, dominant colours, skin regions, saturation distribution, contrast, dynamic range, subject/background separation and lighting. The VLM receives reference observations + target observations + your preferences and returns a grading intent, not numbers:

Retain warm practical highlights, cool ambient background, protect skin, deepen blacks selectively, add local subject separation, avoid a global teal/orange treatment.

The solver then finds parameters. Why this beats LUT transfer: a night-cyan reference applied to a daylight beach would wreck it; the intent “separate warm from cool” instead becomes “increase tonal separation, keep highlights, cool the shadows only where physically plausible.”

11.4 Solver and writers

11.7 Grade QC

Target-statistics distance, clipping percentage, skin-hue deviation from the skin line, temporal stability (per-shot constants only), shot-to-shot consistency, gamut warnings, waveform and vectorscope from rendered frames. Match visual intent, not pixel distributions.

VideoColorGrading as proposer: generate a candidate LUT from a hero frame and reference, score it with the same loss and constraints, use it only if it wins.

12. Edit engine

12.1 Sequencing

Shot choice is an optimisation: per-slot cost (semantic fit, quality, rhythm distance from the profile's median shot, feasibility, mid-word cut, off-beat) plus per-cut cost (same shot size, same camera move, 180-degree flip), solved by a second-order Viterbi search so reuse is penalised two cuts back. Style weights are measured from your reels (median and 10th-percentile shot length, repeat habits), never guessed. Scoring terms: content fit, composition, quality, style fit, motion fit, audio fit, beat fit, narrative value, minus repetition, bad-cut and continuity penalties. The LLM supplies slot intent; the solver places clips.

Beat logic: soft beat → hold; strong beat → candidate cut; drop → major visual change; build → increase density. Not every beat is a cut: your learned style decides. Cuts snap within ±40 ms (starting default).

12.2 Pacing

Store real statistics (median, p10, p90, cuts per minute, long-shot and rapid-cut frequency, beat alignment) and a pacing curve over time. Labels such as fast or restrained are views over the numbers.

12.3 Text-based editing (first-class)

Pipeline: Whisper word timestamps (and Resolve's own transcription with speaker data as cross-check) → transcript editor → semantic search → map words to source time → cut with handles (about 40 ms pre, 80 ms post, zero-crossing, 2–3 frame audio crossfade) → ripple → preserve linked A/V → verify → regenerate captions from the edited transcript.

Natural-language commands become patches: “remove the hotel part”, “make it 22 seconds”, “remove filler words”, “speed up the intro”, “remove overlays from the second half”. Take ranking measures fluency only; performance stays your call.

12.4 Transitions, fades, speed

On 21.1, standard transitions and fades go through the new API calls (G12). Stylised ones (whip, zoom punch, glitch) are Fusion comps on overlapped clips. Speed: constant changes via API (G13); ramps only when verified, else pre-rendered. A ramp must state its purpose (emphasis, transition, energy, motion exaggeration, beat impact) and pick a curve from that purpose (for example 100→40→100 for emphasis), never random.

12.5 Reframing

Static reframe via item properties; dynamic subject-follow via a keyframed Fusion transform compiled from the subject track; Resolve's SmartReframe (async in 21.1.1) as an optional candidate scored by the same critic.

13.3 Placement and legibility

Score candidate positions by distance from faces and subject matte, platform safe zones (set from a current screenshot of the app UI), saliency, your habitual position and contrast against the blurred local background. If a candidate fails, add outline, shadow or backing before moving the text. QC reads the rendered frame back with OCR.

Variants: reveal inside silhouette, footage inside text, wipe reveal, occlusion by objects (SAM text prompt for the occluder).

13.5 Mask engine

Prompt (for example 'the rider on the motorcycle') → SAM 3.1 video segmentation and tracking → temporal smoothing, hole filling, edge feathering, flicker suppression → confidence score → attach to Resolve. Low-confidence shots (hair, glass, motion blur) go to a review queue with positive/negative point correction and re-propagation. Cache by shot ID + source hash + prompt. Magic Mask is the fallback when SAM fails.

13.6 Tracking: use the simplest method that solves it

Point track → planar track → Fusion tracker → external camera solve. A complex 3D solve is justified only when a planar track visibly slips.

13.7 3D hover text, staged

2.5D (reliable): Text+ with soft shadow and measured parallax.

Fusion 3D (Text3D → Merge3D → Camera3D → Renderer3D) with a camera solved outside and imported into the Camera Tracker (G14); OpenPBR materials and Krokodove 3D tools for surface and light.

Depth occlusion: a depth map lets objects pass in front of the text (needs a Z-aware merge; VERIFY).

The planner may choose 3D only with a spatial reason (strong perspective, stable camera, negative space).

13.8 Captions

Word-level karaoke from aligned timestamps, 2–4 word chunks, no orphan words, profile style, OCR round-trip QC.

14. Music engine (song choice)

Index every track in your licensed or owned library: BPM, beat grid, downbeats, sections (intro, build, drop, outro), energy curve, RMS, spectral brightness, key/chroma, loudness, CLAP embedding, duration, and rights metadata (source, licence, platform-cleared yes/no).

Score each candidate against the request (for example “dark cinematic motorcycle night reel, slow first half, hard drop near 11 s”):

Alignment: choose the start offset so a downbeat lands on the first strong cut; end on a bar boundary; when tempo and duration disagree, re-cut the picture to the grid rather than time-stretching the song. Resolve Studio's own AI music-editing tool is an optional alternative for fitting a track to length; score its result with the same critic.

Licence safety: a reference reel's music is analysis input only. Output uses your own music, a licensed library, royalty-cleared tracks or generated audio, with the source recorded. Platform-library trending sounds are not available to Resolve: the system leaves a silent guide track and a marker at the sync point so you add the sound in the app after export. Music generation (MusicGen and similar) is a later fallback; check the weights' licence before any commercial use.

18. Learning loop and measurement

Capture: (1) one-click feedback in Mission Control (thumbs, too much, too little, wrong shot, wrong colour, wrong text, wrong effect, wrong pacing); (2) implicit corrections read from the final timeline (cuts moved, text moved, contrast changed). Grade changes are measured by exporting stills/LUTs and recomputing statistics, since parameters cannot be read directly.

Classify each correction: explicit positive, explicit negative, implicit correction, parameter adjustment, structural correction. Store AI decision, your correction, scene context and a confidence in the inference. Example: contrast 0.72 → 0.55 suggests “grade too aggressive” at confidence about 0.8, not certainty.

Update: rule counts (support and contradiction) move; when the same correction recurs under matching conditions (default: 4 times) a proposed rule enters a review queue; nothing enters the KB silently; rules not reconfirmed for six months are flagged. Negative preferences and exceptions are updated the same way.

Later: train small specialist scorers (shot selection, pacing, colour intensity, typography, effect choice) on your recorded decisions; consider adapters on the planner only after several hundred decisions, always against a held-out set. Fine-tuning the base VLM is a late option, not a start.
